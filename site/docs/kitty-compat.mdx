# kitty 兼容面（超集）

**TGS ⊃ kitty**：能力上包含 kitty（像素呈现），并扩展原语语义、事件与 IME。兼容面分三块，对应规范 §8。

## 1. G 通道共存（双识别，两端）

kitty 原生帧（`Ga=…` 等）在 TGS 通道内**合法**。识别规则在 pty 两端一致：

- `G1;` 前缀 → TGS 帧；其余 `G…` → kitty 原生帧。
- **合成器 parser** MUST 把原生载荷路由给原生接收器，MUST NOT 喂给 TGS 解码器。
- **客户端库**读自己 stdin 时 MUST 消费并跳过非 `G1;` 的 APC 帧——合成器回写的 ACK 会与 READY / EVT 共流；`G1;` 解码失败仍视为流错误。

:::note 两端都要做
双识别最初只做了合成器端，e2e 抓出真 bug：ACK（`Gi=7,OK`）先于握手进入 pty 输入队列，`tgs_client` 把非 `G1;` 帧当流错误、程序握手即死。修复为客户端同款分流，并以 `ClientInput` 测试把该顺序钉进回归——详见[验证抓出的真 bug](./verification#验证抓出的真-bug)。
:::

## 2. 呈现即 kitty

合成器把渲染画布编码为 kitty 图形序列（`Gf=100,a=T,q=2,m=…` PNG base64 分块）推到真终端 stdout：

- 呈现节拍由 `TGS_FPS` 指定（默认 60，支持到 240）；实测 60Hz 59.8fps 精确命中，120 / 240 档经锚点节拍与脏区传输达 **123.7fps / 245.3fps**（见[验证报告](./verification)）。
- raw RGBA 禁用——77MB/s 会淹没终端；PNG 编码走系统 zlib 级 1（约 7ms/帧 800×600）。

## 3. 程序可直用 kitty（接收器已落地）

程序直接发 kitty 原生帧传像素是合法用法，像素直接落画布已在 L0 实现：

- **动作** `a=t/T/p/d`；**格式** `f=100`（PNG，经 stb_image，IHDR 预检：每轴 ≤8192、像素 ≤4M、载荷 ≤8MB）与 `f=32/24`（raw，精确尺寸）。
- **分块**：`m=1..0` 分块 base64 流式拼装（单流）；解析器缓冲 8192 字节以容纳整块 4KB 二进制的 base64（约 5.5KB）。
- **图像槽**：`i=` 共 64 槽，缺省自动 id（≥0x40000000），满则逐出最旧放置；同 id 重传重置放置。
- **放置** = 光标格快照 + `X/Y` 格内像素偏移；`c/r` 为显示尺寸（格为单位，最近邻缩放，缺一轴按纵横比推导）；`x/y/w/h` 为显示裁剪（仅无数据帧——数据帧上的 w/h 是 raw 尺寸、x/y 视为部分传输而拒绝）。
- **顺序**：按 (z, 放置序)。
- **z 序（承重）**：图像在字符底之上、场景元素之下——glyph 绘制之后、场景渲染之前合成进 term-view 像素，底色重绘时无条件重放。
- **ACK**：仅 `i=` 存在时回写 app pty；`q=0` 全部 / `q=1` 仅错误 / `q=2` 静默；码 OK / ENOENT / EINVAL / ENOTSUPPORTED；非阻塞写，满则丢弃。

像素级证据（z 序遮挡 **120000/120000 = 100%，maxdiff=0**）见[验证报告](./verification)。

### 明示缺口

记录而非实现——违者按码表拒绝：

- `U=1` 虚拟放置
- 动画（`a=A/a/f/c`）
- zlib 压缩帧
- 多放置（`p>0`）
- 游标策略 `C=0`（从不移动 vterm 光标）
- 放置与滚动解耦（快照格固定，文本在其下滚动）
- BMP / GIF
- 部分 raw 传输
- file / shm 目标（`t=/o=`）

**实现性边界**：图像层随底色全量重放（暂无图像级脏区）；ACK 在程序不读输入时丢弃（不阻塞循环）；拼装单流。

**仍是 L4 范畴**：作为 GRAPHIC / IMAGE 元素填充源（按 id 引用）。
